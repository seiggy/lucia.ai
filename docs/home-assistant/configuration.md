# Configuration

As of v1.2.0, the Lucia Home Assistant integration has been simplified. Setup now requires only a host URL and API key, with no agent selection UI. The integration talks directly to the new `POST /api/conversation` REST endpoint with structured context.

## Adding the Integration

1. Navigate to **Settings** > **Devices & Services**.
2. Click **Add Integration** (bottom-right corner).
3. Search for **Lucia** and select it.

## Configuration Flow

The setup wizard guides you through the following steps:

### Step 1: Lucia Host URL

Enter the URL of your Lucia agent host. This is the base URL where the agent host API is accessible from your Home Assistant instance.

```
http://192.168.1.100:7233
```

:::tip
If Lucia and Home Assistant are running on the same Docker network, use the container name instead of an IP address: `http://lucia-agenthost:8080`
:::

### Step 2: API Key

Enter the API key you created during the Lucia setup wizard. This key authenticates the Home Assistant integration with the agent host.

:::warning
Home Assistant stores the API key in its internal configuration store. It isn't exposed in YAML files, but treat it as a secret and don't share it.
:::

### REST Integration (v1.2.0+)

Starting in v1.2.0, the integration communicates with Lucia using the `POST /api/conversation` REST endpoint instead of the older JSON-RPC protocol. Each request includes structured context:

- **Device ID**: identifies the device making the request
- **Area**: the location context (e.g., living room)
- **User ID**: authenticated user identifier
- **Timestamp**: request time for temporal awareness
- **Location**: optional GPS coordinates
- **Device Type**: entity domain (light, climate, etc.)

Lucia's command parser uses this structured context to pattern-match common commands (lights, climate, scenes) and execute them directly against Home Assistant, or fall back to LLM orchestration for complex requests. Responses are templated and returned as instant JSON (for parsed commands) or Server-Sent Events for LLM streaming.

### Multi-Turn Continuity

Conversation IDs are auto-generated by Lucia for first-turn requests and maintained across follow-ups. This enables multi-turn conversation continuity: the agent understands context from previous exchanges in the same conversation thread.

### Step 3: Set as Conversation Agent

After adding the integration, set Lucia as your default conversation agent:

1. Navigate to **Settings** > **Voice assistants**.
2. Select your assistant (or create a new one).
3. Under **Conversation agent**, select **Lucia**.
4. Click **Save**.

Lucia will now handle all voice and text commands routed through this assistant.

## `lucia.send_message` Service

Version 1.2.3 adds Home Assistant service metadata for `lucia.send_message`, so the service appears in the automation and Developer Tools UI with a multiline **Message** field.

```yaml
action: lucia.send_message
data:
  message: "Turn on the living room lights"
```

## Reconfiguring

To change settings after initial setup:

1. Go to **Settings** > **Devices & Services**.
2. Find the **Lucia** integration.
3. Click **Configure**.
4. Update the Lucia host URL or API key.

## Multiple Instances

You can add the Lucia integration multiple times if you run separate agent host instances (for example, one for upstairs and one for downstairs). Each instance gets its own configuration entry with its own URL and API key.

## Troubleshooting

| Issue | Solution |
|---|---|
| Integration not found after install | Restart Home Assistant and clear browser cache. |
| Connection refused | Verify the agent host URL is reachable from HA. Check firewalls and Docker networking. |
| Authentication failed | Regenerate the API key in the Lucia dashboard and re-enter it in HA. |
| Home Assistant WebSocket authentication fails | Verify the long-lived Home Assistant token in Lucia; v1.2.3 validates it before opening the socket and reports authentication failures directly. |
