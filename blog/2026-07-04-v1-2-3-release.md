**Lucia v1.2.3** adds dedicated Sensor and Security agents, per-user memory, PostgreSQL storage, filtered entity APIs, and a broad set of production fixes.

<!-- truncate -->

## New capabilities

- **Sensor Agent** reads Home Assistant sensors and binary sensors by name, area, or device type.
- **Security Agent** arms and disarms alarm panels, controls locks, and reports security status.
- **Per-user memory** gives the conversation pipeline durable user-specific context with authenticated CRUD endpoints.
- **PostgreSQL provider** joins SQLite and MongoDB as a persistent store option.
- **Entity query API** adds pagination and name, location, domain, and agent filters.
- **Enhanced-clip STT** can optionally re-transcribe GTCRN-enhanced utterance audio.
- **Home Assistant service metadata** exposes `lucia.send_message` correctly in the Home Assistant UI.

## Reliability and security

Docker images now create writable model directories, use working health checks, persist voice models, and include a MongoDB workaround for Linux kernel 6.19+. Lucia also caps utterance buffers, persists dashboard session signing keys, validates Home Assistant tokens before opening WebSockets, and returns clear errors for malformed agent URLs, MCP failures, list-provider fallbacks, and dashboard loading failures.

Tasks waiting for user input now auto-cancel after a configurable timeout. `DASHBOARD_API_KEY` can reset a lost dashboard key, including PostgreSQL, SQLite, and MongoDB deployments.

There are no intentional breaking changes. See the [full GitHub release](https://github.com/seiggy/lucia-dotnet/releases/tag/v1.2.3).
